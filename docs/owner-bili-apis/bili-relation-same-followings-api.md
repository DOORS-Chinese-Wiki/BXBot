# 共同关注列表

## 接口描述

获取当前登录用户与目标用户的共同关注列表。

> 该接口位于主站 API 域名 `api.bilibili.com`，用于获取你和目标用户共同关注的 UP 主列表。**不受对方关注列表隐私设置影响，也不受 Web 端关注列表前 100 条限制。**

---

## 接口地址

```
GET https://api.bilibili.com/x/relation/same/followings
```

- **请求方式**：GET
- **认证方式**：Cookie（需携带 `SESSDATA`）
- **Content-Type**：`application/json`
- **是否需要 WBI 签名**：❌ 不需要

---

## 请求参数（URL Query）

| 参数名 | 类型 | 内容               | 必要性     | 备注                                          |
| ------ | ---- | ------------------ | ---------- | --------------------------------------------- |
| `mid`  | num  | 目标用户的 UID     | **必要**   | 要查询共同关注的对方用户                      |
| `vmid` | num  | 当前登录用户的 UID | **非必要** | 不传时自动从 Cookie（SESSDATA）中获取当前用户 |
| `pn`   | num  | 页码               | 非必要     | 默认 1                                        |
| `ps`   | num  | 每页数量           | 非必要     | 默认 50，建议 50                              |

---

## 请求示例

```bash
curl 'https://api.bilibili.com/x/relation/same/followings?mid=1447574&vmid=3690995472402999&pn=1&ps=50' \
  -X GET \
  -H 'Referer: https://space.bilibili.com/' \
  -H 'Origin: https://space.bilibili.com' \
  -b 'SESSDATA=xxx'
```

---

## 响应结构

### 根对象

| 字段      | 类型 | 内容     | 备注                                                |
| --------- | ---- | -------- | --------------------------------------------------- |
| `code`    | num  | 状态码   | 0 表示成功                                          |
| `message` | str  | 状态信息 | 成功时返回 `"0"`（注意是字符串 `"0"`，不是 `"OK"`） |
| `ttl`     | num  | 缓存时间 | 1                                                   |
| `data`    | obj  | 数据本体 |                                                     |

### `data` 对象

| 字段         | 类型  | 内容         | 备注                       |
| ------------ | ----- | ------------ | -------------------------- |
| `list`       | array | 共同关注列表 | 每个元素包含 UP 主详细信息 |
| `re_version` | str   | 版本标识     | 通常为空                   |
| `total`      | num   | 共同关注总数 |                            |

### `list` 数组项（UP 主信息）

| 字段              | 类型  | 内容               | 备注                                    |
| ----------------- | ----- | ------------------ | --------------------------------------- |
| `mid`             | num   | UP 主 UID          |                                         |
| `attribute`       | num   | 关系属性           | 2 = 正常关注                            |
| `mtime`           | num   | 关注时间戳         | Unix 时间戳（秒）                       |
| `tag`             | array | 分组标签 ID 列表   | `-10` 表示特别关注；正数为自定义分组 ID |
| `special`         | num   | 是否特别关注       | `0` = 普通关注，`1` = 特别关注          |
| `uname`           | str   | UP 主昵称          |                                         |
| `face`            | str   | 头像 URL           |                                         |
| `sign`            | str   | 个人简介           |                                         |
| `face_nft`        | num   | 是否为 NFT 头像    | `0` = 否                                |
| `handle`          | str   | 用户 handle        | 通常为空                                |
| `official_verify` | obj   | 官方认证信息       |                                         |
| `vip`             | obj   | 大会员信息         |                                         |
| `name_render`     | obj   | 昵称渲染信息       | 通常为空                                |
| `nft_icon`        | str   | NFT 图标           | 通常为空                                |
| `rec_reason`      | str   | 推荐理由           | 通常为空                                |
| `track_id`        | str   | 追踪 ID            | 通常为空                                |
| `follow_time`     | str   | 关注时间（字符串） | 通常为空                                |

### `official_verify` 对象

| 字段   | 类型 | 内容     | 备注                           |
| ------ | ---- | -------- | ------------------------------ |
| `type` | num  | 认证类型 | `-1` = 无认证，`0` = UP 主认证 |
| `desc` | str  | 认证描述 |                                |

### `vip` 对象

| 字段               | 类型 | 内容       | 备注                                         |
| ------------------ | ---- | ---------- | -------------------------------------------- |
| `vipType`          | num  | 大会员类型 | `0` = 无，`1` = 月度大会员，`2` = 年度大会员 |
| `vipDueDate`       | num  | 到期时间戳 | 毫秒                                         |
| `vipStatus`        | num  | 状态       | `0` = 未激活/已过期，`1` = 生效中            |
| `label`            | obj  | 标签信息   | 包含样式和文本                               |
| `avatar_subscript` | num  | 头像角标   | `0` = 无，`1` = 有                           |
| `nickname_color`   | str  | 昵称颜色   | 大会员粉色 `#FB7299`                         |

## 字段详解

### `tag` 字段含义

| 值     | 含义                                     |
| ------ | ---------------------------------------- |
| `-10`  | **特别关注**（与 `special: 1` 同时出现） |
| `正数` | 自定义关注分组的 ID（如 `353738545`）    |

### `special` 字段

| 值   | 含义                                          |
| ---- | --------------------------------------------- |
| `0`  | 普通关注                                      |
| `1`  | **特别关注**（与 `tag: [-10, ...]` 同时出现） |

## 注意事项

1. **需要登录态**：必须携带有效的 `SESSDATA` Cookie，否则返回 `-101`。
2. **`mid` 是对方，`vmid` 是你自己**：参数名容易混淆，注意区分。
3. **受隐私设置影响**：如果对方关闭了“公开关注列表”，共同关注接口不可用。
4. **不受前 100 限制**：Web 端关注列表最多只能查前 100 个，共同关注接口可以查全部共同关注。
5. **依赖你的关注列表**：只有当“你关注了某人”且“对方也关注了此人”时，才会出现在共同关注列表里。
6. **分页遍历**：共同关注数量较多时，需要循环翻页获取全部。
7. **`tag` 字段可识别特别关注**：`-10` 表示特别关注，可用于判断用户的关注优先级。
